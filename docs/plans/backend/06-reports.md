# Phase 06 — Report Generation & `/reports` Endpoints

> **Status:** broad plan · **Depends on:** Phase 02 (endpoint shell) and Phase 05 (content) ·
> **Unblocks:** Phase 07
> Canonical references: `docs/API_SPEC.md` §2.6/§8/§11, `docs/ARCHITECTURE.md` §8/§12,
> `docs/SECURITY.md` §8, `docs/TEST_PLAN.md` T-REP / T-OWN.

---

## 1. Objective

Implement async, user-triggered **PDF-only** report generation for completed documents, expose
the `/reports` endpoints, and keep the report file lifecycle (creation, signed download, deletion
with the document) consistent.

---

## 2. Scope

**In:** `ReportController` + routes, `GenerateDocumentReportJob`, report data building, Blade →
HTML rendering + Gotenberg PDF conversion behind an interface, file storage/linkage, report
DTOs/requests, file cleanup on document delete.

**Out:** report templates beyond v1 content, DOCX/Excel export (excluded), frontend rendering.

---

## 3. Deliverables

### 3.1 Endpoints

| Action | Route | Status | Notes |
|---|---|---|---|
| `ReportController@store` | `POST /documents/{document}/reports` | 202 | only when document `completed`, else 409 |
| `ReportController@index` | `GET /documents/{document}/reports` | 200 | paginated |
| `ReportController@show` | `GET /reports/{report}` | 200 | detail incl. `error` |
| `ReportController@destroy` | `DELETE /reports/{report}` | 204 | deletes row + stored file |

- Ownership: report → document → user; foreign access `404` (`ResourceNotFoundException::report()`).
- `store` behaviour per `docs/API_SPEC.md` §8: create the report row (`pending`), dispatch the job
  **after commit**, respond immediately with
  `{ id, document_id, status, generated_at }` + `"Laporan sedang dibuat."`.
- State guard: document must be `completed`; otherwise `409 CONFLICT` with
  `"Laporan hanya dapat dibuat untuk dokumen yang selesai dianalisis."`.
- `index` item shape: `id`, `document_id`, `status`, `download_url`, `generated_at`; `meta` from
  the shared collection envelope.
- `show` adds `error` (safe message when failed).
- `download_url` is a signed/temporary URL for the stored PDF (private disk only); `null` until
  `completed`.

### 3.2 Job — `App\Jobs\GenerateDocumentReportJob`

- `$tries = 1`, config timeout, `WithoutOverlapping("report-generation:{$reportId}")`.
- Entry guard: report + document still exist; report status not already terminal; document still
  `completed` (deleted documents abort quietly; ownership is implicit — jobs only run for rows
  that exist).
- Transitions: `pending → processing → completed | failed`.
- On success: set `status=completed`, `generated_at=now()`, `error=null`, attach the file.
- On failure: `status=failed`, `error` = safe user-facing message; log the raw exception with
  report/document ids. A failed report can be regenerated by calling `store` again (OQ-07
  resolved).
- Queue/config: `reports.queue` (recommendation: default queue, separate from `analysis`).

### 3.3 Data building and rendering — `app/Services/Reports/`

| Artifact | Responsibility |
|---|---|
| `ReportDataBuilder` | builds the view model from the document + summary + references/findings + citations (all derived, reuses Phase 02 summary and Phase 05 resolvers) |
| `ReportRenderer` (interface) | `render(string $html): string` returning PDF bytes |
| `GotenbergReportRenderer` | default adapter (OQ-05): POSTs the rendered HTML to Gotenberg `/forms/chromium/convert/html` and returns the PDF |
| `GotenbergClient` | config-driven HTTP client for Gotenberg (base URL, connect/read timeouts); non-2xx/timeout → report rendering failure |
| `ReportFileManager` | stores the PDF on the private disk, creates the `files` row, deletes files safely (shared pattern with Phase 02) |

Content (v1; OQ-16 resolved): document info (name, dates, status), summary counts, reference
table (raw text, DOI, finding status, confidence, reason), citation issues (text, derived status,
linked reference). Indonesian output, isolated Blade view
(`resources/views/reports/document-report.blade.php`) so layout changes never touch the job.

Rendering flow: Blade → HTML string → `GotenbergReportRenderer` → Gotenberg Chromium → PDF bytes
→ private disk. Gotenberg supports modern CSS, so the template can use current layout techniques;
keep the HTML **self-contained** (inline CSS, no external asset URLs, no JS that needs the app
server) because the Gotenberg container cannot fetch private app assets. Extracted document text
is untrusted — Blade escapes by default and `{!! !!}` must not be used.

### 3.4 File linkage (OQ-06 resolved)

- `generated_document_reports.file_id` is the canonical pointer (`docs/API_SPEC.md` §11) **and** a
  polymorphic `files` row is kept for uniform file handling; the migration adds a nullable FK
  `file_id → files.id` (`nullOnDelete`) and `docs/DB_SCHEMA.md` is updated in the same change.
- `ReportFileManager` keeps both pointers consistent.
- Deleting a report deletes the DB row and the stored object; deleting a document also removes its
  reports' files (Phase 02 `DocumentFileManager` must cover report files).

### 3.5 Requests/DTOs

- `ListReportsRequest` — pagination only (validate `per_page` ≤ 100); invalid input → `422`.
- `App\Data\Report\GeneratedDocumentReportSummaryData` (list item) and
  `GeneratedDocumentReportDetailData` (detail + `error`), snake_case mapping.

### 3.6 Config

- `config/reports.php`: `disk` (default `filesystems.default`), `queue`, `template`, optional
  `paper_size`/`orientation`/`margins` passed to Gotenberg.
- `services.gotenberg.*` (`base_url`, `timeout`, `connect_timeout`, created in Phase 01) consumed
  by `GotenbergClient`.
- `.env.example` placeholders only (`GOTENBERG_URL`, `GOTENBERG_TIMEOUT`, …).
- Gotenberg is an internal service: keep it on the private network like inference and add the
  corresponding note to `docs/SECURITY.md` §7 when implemented.

## 4. Contracts & invariants

- Reports only for `completed` documents; otherwise `409`.
- Report generation is asynchronous; `store` never renders inline.
- Report status is one of `pending|processing|completed|failed`.
- Gotenberg is internal/private (same rule as inference); the report HTML is generated server-side
  and never rendered in the browser.
- `download_url` is signed/temporary; no public path, no secret in logs.
- Hard delete removes rows + stored file; no orphans (tested).
- One report row per generation request; content covers the whole document (OQ-07 resolved).

## 6. Decisions (resolved)

- **OQ-05** — **Gotenberg** renders the Blade HTML (`/forms/chromium/convert/html`); no Dompdf.
- **OQ-06** — `file_id` is canonical + a polymorphic `files` row is kept; add the FK migration and
  update `docs/DB_SCHEMA.md`.
- **OQ-07** — multiple report rows allowed; failed reports can be regenerated.
- **OQ-08** — `generating_report` is bookkeeping only; no auto-generated report.
- **OQ-16** — Indonesian content and the sections listed in §3.3.

---

## 7. Risks

- Gotenberg is a required service dependency: reports fail while it is unavailable — the job marks
  the report `failed` with a safe error and the user can regenerate. Keep it private, on the same
  network as the queue worker.
- The report HTML must be self-contained (inline CSS/assets); Gotenberg Chromium cannot fetch
  private app assets or authenticated URLs.
- Large documents produce large HTML/PDF; bound repeated `raw_text` previews and keep the job
  timeout configurable.
- Signed URLs depend on a correct `APP_URL`; cover the URL shape in tests (signed URLs are
  time-limited).
- Multiple report rows (OQ-07 resolved) keep `GET /documents/{id}/reports` a true paginated
  collection and avoid an idempotency conflict in `store`.
